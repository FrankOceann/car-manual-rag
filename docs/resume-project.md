# 简历项目描述：汽车维修手册 RAG

## 一句话介绍

面向多车型维修手册的本地 RAG 问答演示系统。用户选择车型并提问，系统只从该车型已导入 PDF 中检索证据，调用 DeepSeek 生成回答，同时返回可核对的 PDF 页码与原文节选。

## 简历写法

**汽车维修手册 RAG 问答系统｜React、FastAPI、ChromaDB、DeepSeek**

- 使用 React + FastAPI 搭建前后端分离的车型手册问答系统，完成 PDF 文本提取、分块、向量化、车型隔离检索和带页码引用的回答展示。
- 结合 Sentence Transformers 向量检索、BM25、RRF 融合、相似度阈值和引用去重，限制回答仅使用检索到的最多 4 条证据，资料不足时返回拒答结果。
- 构建 14 道人工页码标注的离线评测题集，使用 Recall@1、Recall@3、MRR、候选引用精度与拒答准确率量化检索效果；通过零分 BM25 回退和中英汽车术语扩展，将 Recall@1 从 0.40 提升至 0.70，MRR 从 0.60 提升至 0.75。

## 面试讲解顺序

1. **问题**：通用聊天机器人容易把其他车型资料混入答案，且回答无法核对来源。
2. **方案**：车型 ID 作为向量库过滤条件；PDF 按页提取、分块并保留车型、手册名、章节和页码元数据。
3. **检索**：先做多语言向量召回，再将有效 BM25 词法结果与向量结果通过 RRF 融合；没有词法命中时回退向量排序，避免零分排序干扰。
4. **生成与引用**：将候选片段附带 chunk ID 交给 DeepSeek，要求模型回传引用 ID；服务端只接受合法 ID，并按手册和页码去重。
5. **评测与反思**：用人工校验的页码题集比较策略。混合检索提升首条命中率和 MRR，但 Recall@3 略低于基线，因此保留真实数据和指标，不夸大结果。

## 可现场演示的问题

- 思域：如何检查发动机机油液位？
- 思域：跨接启动应使用多少伏的辅助电池？
- 思域：紧急拖车时应该使用哪种运输设备？
- 卡罗拉：紧急驾驶停止系统在什么情况下启动？
- 海豹：标准轮胎气压是多少？（展示资料未导入时的拒答）

## 项目边界

这是简历展示项目，不是可直接指导维修作业的生产系统。只使用用户本地取得、且在 `docs/data-sources.md` 中标记为可用的资料；完整原厂 PDF 和本地向量库不提交到仓库。
