# RAG 检索质量与引用控制设计

## 目标

为本地汽车手册 RAG 建立可重复运行的检索评测，并将查询改造成车型隔离、可选章节过滤、混合检索、融合重排序、阈值拒答和引用去重的流程。

成功标准是：每次修改检索策略后，都能用固定题集比较指标；接口只返回被回答实际使用且不重复的引用；无资料或低置信问题保持安全拒答。

## 范围与边界

本阶段不新增原厂资料，不改变车型目录，不实现用户登录、云部署或 PDF 上传界面。评测使用仓库内的人工题集，题目只能引用本机已获准导入的资料页码。

首批评测覆盖本田思域和丰田卡罗拉的已导入资料，并包含比亚迪海豹的拒答题。海豹没有本地资料时，任何海豹题都必须没有证据、没有引用并返回 `grounded: false`。

## 基准题集

题集位于 `backend/evals/cases.yaml`，每个条目包含：

```yaml
id: toyota-emergency-driving-stop
vehicle_id: toyota-corolla
question: 紧急驾驶停止系统何时可能启动？
expected_pages: [16, 17]
expected_chapters: ["第 16 页", "第 17 页"]
should_grounded: true
```

拒答条目将 `expected_pages` 和 `expected_chapters` 设为空，并将 `should_grounded` 设为 `false`。首批题集至少包含：6 道本田命中题、4 道卡罗拉命中题和 4 道拒答题。每道命中题必须由人工从已导入 PDF 中核对页码和章节。

## 检索流水线

`RetrievalOptions` 是检索的显式输入，包含 `limit`、可选的 `chapter_titles` 和阈值配置。`POST /chat` 增加可选 `chapter_titles` 字段；未提供时仍检索该车型的全部章节。

1. 先按 `vehicle_id` 读取候选块；指定章节时只保留这些章节。
2. 对同一候选集执行向量排序和 BM25 关键词排序。
3. 使用 Reciprocal Rank Fusion 合并两个排序；固定 `k=60`，避免依赖外部重排序模型。
4. 将融合前列结果按向量距离阈值过滤。低于最小证据数时返回空证据，触发既有安全拒答。
5. 返回最多 4 个证据块给回答层。

该方案不增加新云模型、密钥或网络依赖；BM25 只对本地该车型候选块计算。向量距离阈值默认保持现有 `1.1`，并由评测报告调整，而不是凭感觉修改。

## 引用控制

回答提示词为每个证据提供稳定 `chunk_id`，并要求模型返回 `citation_ids`。后端仅接受属于当前证据集的 ID；非法、空或缺失的 ID 会退回为按排名选择的唯一页码引用。

引用的唯一键为 `manual_title + page_number`。同一页的多个相邻块只保留排名最高的一条，保证每个引用都指向不同手册页。`ChatResponse` 的公开结构保持不变。

## 评测与报告

新增 `scripts/evaluate_retrieval.py`，读取题集并针对当前本地向量库运行两种模式：`baseline`（当前纯向量排序）和 `hybrid`（新流水线）。它不调用 DeepSeek，因此不会产生模型费用。

每次运行输出 JSON 和 Markdown 报告，记录：

- `Recall@1`、`Recall@3`：前 1/3 个证据是否命中任一预期页。
- `MRR`：第一个预期页的倒数排名；未命中计 0。
- `citation_candidate_precision`：返回前 4 个去重候选中属于预期页的比例。
- `refusal_accuracy`：应拒答题是否返回空证据；命中题是否至少返回一条证据。

报告按车型和总体汇总，并保留每题的命中页、返回页、排名和失败原因。它只将评测结果写到本地 `backend/data/eval-reports/`，该目录不提交到 Git。

## 错误处理

题集中的未知车型、空问题、缺少期望页码的命中题、或未导入车型的命中题均为评测配置错误，命令以非零状态退出并指出题目 ID。章节过滤没有任何候选块时属于正常无证据结果，不跨章节或跨车型补充资料。

## 测试与验收

单元测试覆盖：车型过滤、章节过滤、BM25 排序、RRF 融合、阈值拒答、同页引用去重和非法 `citation_ids` 回退。评测脚本测试覆盖指标计算、拒答题和配置错误。

验收时运行完整后端测试、前端测试和前端构建；导入后的卡罗拉与思域题至少各运行一次真实检索评测。最终报告必须能显示基线与混合检索的数值，并且不得让海豹拒答题返回跨车型证据。
